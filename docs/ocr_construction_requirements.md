# 建設向け OCR 体験デモ — テーマ別要件定義書

## 背景

建設現場では、作業員が写真を内勤へ送り、内勤が Word / 帳票へ転記して報告書や朝礼メモを作成している。転記コスト・漏れ・属人化が課題になる。

## 課題

- 複数枚の現場写真から、手作業で報告書を組み立てる必要がある
- 朝礼で伝える安全ポイント・重点作業の整理に時間がかかる
- デモ商談では「アップロードしたくない」「キー設定が面倒」で体験が止まりやすい

## 対象ユーザー

- Primary: 建設事業者の内勤・現場管理・営業（導入検討者）
- Secondary: 現場監督・職長（写真を送る側）

## 業務シナリオ

1. 現場から当日分の写真が届く
2. 内勤が写真を確認し、報告書 / 朝礼メモの下書きを AI が作成
3. 要確認欄だけ人が直して提出・PDF 化

## デモの目的

現場写真を置くだけで、テンプレ下書きまで完成し、要確認だけ直して提出・PDF 化できることを体験してもらう。

## 理想感情

「もう転記しなくていい」

## Must / Should / Won't

### Must

- 報告書作成 / 朝礼向けの 2 モード
- 複数写真（最大 5）→ 報告書テンプレ下書き
- テキスト編集
- 要確認欄の黄色ハイライト
- サンプル 1 クリック（チャット到着演出付き）
- Before/After 対比（手作業約 15 分 vs AI 約 20 秒）
- 提出完了アニメ（下書き → 確認済 → 提出済）
- 印刷 / PDF として保存
- 朝礼モード同等フロー
- 既存 OCR 項目は詳細データタブで維持

### Should

- 欄が順に埋まる演出
- 提出後の「内勤の転記が不要」メッセージ
- 提出後の投資回収導線（`roi-simulator` へ別タブ。`NEXT_PUBLIC_ROI_SIMULATOR_URL` 設定時）

### Won't（Phase 1）

- `@axeon/ai-demo-core` / Trial 接続
- 音声読み上げ
- 昨日日報との差分ハイライト
- 朝礼後チェックリスト自動生成
- 本物のチャットサーバー連携
- PDF バイナリのサーバー生成

## 技術要件

- Next.js App Router（既存 `ocr-demo-nextjs`）
- 実画像経路: OpenAI Vision（サーバー API）
- サンプル経路: クライアント側モック（API キー不要）
- 画像はサーバーに保存しない

## 成功条件

- キーなしでサンプル再生が最後まで通る
- 実画像でも下書き → 編集 → 提出 → 印刷ができる
- 「このまま出せる」報告書 / 朝礼メモが見える
